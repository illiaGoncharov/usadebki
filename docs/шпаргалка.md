# Шпаргалка: код и база

Секреты **только в `.env`** (в git не попадает). В репозитории — команды ниже.

## Переменные в `.env`

| Переменная | Для чего |
|------------|----------|
| `DATABASE_URL` | локальный Postgres (`localhost:5434`) — `npm run dev`, импорт, обогащение |
| `NEON_DATABASE_URL` | pooled-строка из [Neon](https://console.neon.tech) → Connect → Copy — **только** заливка на прод |
| `CARTO_KEY` | карта (локально и на Vercel) |
| `ADMIN_PASSWORD`, `ADMIN_SECRET` | админка |

На Vercel те же имена, кроме `NEON_DATABASE_URL`: там в `DATABASE_URL` как раз Neon.

## Обновить **сайт** (код)

```bash
git add .
git commit -m "что поменял"
git push
```

Vercel сам пересоберёт проект за 1–3 минуты.

## Обновить **базу на Neon** (данные с Mac)

После импорта, скриптов или правок в **локальном** Docker:

```bash
npm run db:sync-neon
```

Это по очереди: `db:dump` (снимок в `data/usadebki.dump`) → `db:push-neon` (заливка в Neon по `NEON_DATABASE_URL`).

Прод сразу читает Neon — отдельный деплой для данных не нужен.

### По шагам

```bash
npm run db:dump          # только дамп
npm run db:push-neon      # только заливка (если дамп уже есть)
npm run db:sync-neon      # дамп + заливка
```

Предупреждения `pg_restore` вроде «already exists» на уже заполненной базе обычно норм. В Neon SQL Editor:

```sql
select count(*) from estates;
```

Ожидаемо около **4088**.

### Писать сразу в Neon (без дампа)

В `.env` можно временно поставить Neon в `DATABASE_URL` и гонять скрипты:

```bash
npm run import:egrkn
# или SITELINKS_ONLY=1 ENRICH_REGION=all node --env-file=.env --import tsx scripts/enrich-wikidata.ts
```

Не забудь вернуть локальный `DATABASE_URL` для повседневной разработки.

## Обновить **секреты на Vercel**

Vercel → проект → **Settings → Environment Variables** → **Redeploy** (без `git push`).
