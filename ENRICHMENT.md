# Обогащение данных усадеб

Этот документ описывает процесс обогащения каталога усадеб фотографиями, текстами и метаданными.

## Скрипты

### `npm run enrich:all`

Основной скрипт обогащения. Собирает данные из всех доступных источников.

**Источники фотографий** (в порядке приоритета):
1. **Wikidata (P18)** — прямые фото объектов из Wikidata (проверены по depicts)
2. **Wikivoyage RU** — фото из списков культурного наследия (по ЕГРОКН номеру)
3. **ЕГРОКН raw_json** — официальные фото из паспортов реестра
4. **Фото частей ансамбля** — fallback: если у усадьбы нет фото, берём фото флигелей, церквей и других частей (помечаются отдельно)

**Источники текста**:
1. **Wikipedia RU (через article в SPARQL)** — вступления статей, если есть прямая ссылка
2. **Wikipedia RU (через sitelinks)** — вступления статей для объектов с QID, но без прямой ссылки
3. **ЕГРОКН паспорт** — краткие справки из полей: дата, архитектор, статус, адрес (только если нет текста из других источников)

**Стили**:
1. **Wikidata (P149)** — архитектурные стили из Wikidata
2. **Извлечение из текста Wikipedia** — стили, найденные в текстах описаний

**Параметры окружения**:
- `ENRICH_REGION=50` — обработать только регион 50 (Московская область)
- `ENRICH_REGION=all` — обработать все регионы (по умолчанию)
- `ENRICH_WIKIVOYAGE=1` — включить обогащение из Wikivoyage RU (требует доступа к ru.wikivoyage.org)

**Примеры**:
```bash
# Все регионы
npm run enrich:all

# Только Московская область
ENRICH_REGION=50 npm run enrich:all

# Костромская область
ENRICH_REGION=44 npm run enrich:all
```

### `npm run enrich:stats`

Скрипт для сбора статистики покрытия.

Показывает:
- Общее количество усадеб
- Количество и процент усадеб с фото
- Количество и процент усадеб с текстом
- Разбивку фото по источникам (commons, egrkn, commons-ensemble)
- Топ-20 регионов по количеству усадеб с подробностями
- Топ-10 регионов с наибольшим количеством усадеб без фото

**Пример**:
```bash
npm run enrich:stats
```

### `npm run enrich:mo`

Старый скрипт обогащения для Московской области. Работает аналогично `ENRICH_REGION=50 npm run enrich:all`, но с меньшим количеством источников.

**Основные отличия от `enrich:all`**:
- `enrich:mo` работает только с одним регионом через переменную `ENRICH_REGION` (по умолчанию 50)
- `enrich:all` поддерживает все регионы и дополнительные источники (ЕГРОКН фото/паспорта, фото частей ансамблей)

Рекомендуется использовать `npm run enrich:all` для более полного покрытия.

## Атрибуция фотографий

Все фотографии сохраняются с полной атрибуцией и флагами:

- `author` — автор фото или источник (напр. "Wikimedia Commons", "ЕГРОКН")
- `license` — лицензия (напр. "CC BY-SA 4.0", "Публичное достояние")
- `sourceUrl` — URL страницы с полной информацией о фото
- `origin` — тип источника:
  - `commons` — Wikimedia Commons (через Wikidata P18)
  - `wikivoyage` — Wikivoyage RU списки наследия
  - `egrkn` — ЕГРОКН (официальный реестр)
  - `commons-ensemble` — Commons, но фото части ансамбля
- `isEnsemblePart` — true если это фото части ансамбля (флигель, церковь и т.д.), не основного объекта
- `isHidden` — true если администратор скрыл неправильное фото
- `depictsEgrknNumber` — ЕГРОКН номер объекта, которому фото действительно принадлежит (для ensemble part)

Эта информация должна отображаться в UI при показе фотографий.

## Справочные тексты из ЕГРОКН

Для усадеб без текста из Wikipedia генерируются краткие справки из паспорта ЕГРОКН:

- Дата создания
- Архитектор
- Статус охраны
- Адрес

Такие тексты помечаются `summarySource: "egrkn-passport"` и должны отображаться в UI со специальной пометкой "Справочные данные" или "Из реестра", чтобы отличать их от полноценных статей.

## Rate Limiting и производительность

Скрипт автоматически добавляет задержки между запросами:

- Wikidata SPARQL: 300-350 мс между пакетами по 20-25 объектов
- Wikipedia REST API: 120-250 мс между запросами
- Commons API: 200-300 мс между пакетами

Обработка всех регионов может занять несколько часов. Скрипт выводит прогресс и можно остановить/продолжить для отдельных регионов.

## Безопасность матчинга фотографий

**Критическое исправление**: в предыдущих версиях фото из категорий Commons ансамбля прикреплялись ко ВСЕМ объектам ансамбля без проверки. Это приводило к показу неправильных фотографий (например, фото жёлтого двухэтажного здания вместо бежевого трёхэтажного).

**Текущая реализация**:
- Берутся только **прямые P18** фото из Wikidata (проверенные вручную редакторами)
- Фото из категорий Commons **НЕ берутся** автоматически (требуют проверки depicts/coordinates через SDC)
- Фото частей ансамбля **помечаются отдельно** (`isEnsemblePart: true`) и показываются в отдельном блоке UI

**Будущее**: для безопасного использования категорий Commons нужна проверка через Structured Data (depicts P180, coordinates). См. заготовку в `scripts/sources/commons-structured-data.ts`.

## Недоступные источники

**PastVu**: фотографии PastVu имеют ограничения лицензии (некоммерческое использование), поэтому НЕ должны загружаться напрямую. Если в будущем понадобится интеграция, фото PastVu следует показывать только как превью со ссылками и пометкой для ручной проверки лицензии.

## Расширение

Для добавления нового источника данных:

1. Создайте модуль в `scripts/sources/<название>.ts`
2. Экспортируйте функцию извлечения данных
3. Добавьте вызов в `scripts/enrich-all-sources.ts` в функцию `main()`
4. Не забудьте:
   - Rate limiting (задержки между запросами)
   - Обработку ошибок (try/catch)
   - Проверку лицензий (только свободные или совместимые)
   - Полную атрибуцию (author, license, sourceUrl, origin)
